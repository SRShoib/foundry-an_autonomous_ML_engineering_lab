# churn.csv

Synthetic telecom churn dataset generated by [scripts/make_sample_data.py](../../scripts/make_sample_data.py)
with `numpy.random.default_rng(20260726)`. Deterministic — regenerating produces byte-identical
output. 1200 rows, 12 columns, 28.1% churn.

## Columns

| column | type | notes |
|---|---|---|
| `customer_id` | str | `CUST-00001`… unique per row. Not a feature — a leakage trap the data team must flag and drop. |
| `tenure_months` | int | 1–72 |
| `monthly_charges` | float | 18.50–118.75 |
| `total_charges` | float | ≈ `tenure × monthly × (0.97–1.03)`; blank for brand-new customers (`tenure_months == 1`, ~15 rows) |
| `contract_type` | categorical | `month_to_month` .55 / `one_year` .25 / `two_year` .20 |
| `payment_method` | categorical | `electronic_check` .35 / `mailed_check` .20 / `bank_transfer` .22 / `credit_card` .23 |
| `internet_service` | categorical | `dsl` .38 / `fiber_optic` .44 / `none` .18 |
| `num_support_tickets` | int | Poisson(1.6), clipped to 0–12 |
| `avg_monthly_gb` | float | Gamma(3, 40); **missing whenever `internet_service == "none"`** (~194 rows, ~16%) — structural, not random, so it forces a real imputation strategy rather than a global mean |
| `is_senior` | int | 0/1, p = .16 |
| `has_dependents` | int | 0/1, p = .30 |
| `churned` | int | **target**, ~28% positive |

## Generative model

```
logit = -3.4 - 0.055*tenure + 0.030*monthly + 1.5*(contract == month_to_month)
        + 0.8*(payment == electronic_check) + 0.7*(internet == fiber_optic)
        + 0.28*tickets - 0.6*has_dependents + 0.4*is_senior
        + 1.4*((tenure < 12) & (contract == month_to_month))   # genuine interaction
        + N(0, 0.25)
churned ~ Bernoulli(sigmoid(logit))
```

The interaction term (new customers on month-to-month contracts churn disproportionately) means
a plain linear model captures most, but not all, of the signal.

## Measured 5-fold stratified CV (roc_auc, sklearn 1.9.0 — the sandbox image's pin)

| model | roc_auc |
|---|---|
| logistic_regression | 0.853 |
| gradient_boosting | 0.830 |
| random_forest | 0.827 |

The linear baseline winning is deliberate: it lets the principal reach `diminishing_returns`
honestly after a few experiments instead of climbing forever. `DatasetSpec.target_value = 0.90`
(see [foundry/datasets.py](../../foundry/datasets.py)) is set above all three, so `target_met`
stays a reachable-but-unmet stop condition rather than firing on the first result.

# churn_leaky.csv

M5's red-team fixture, generated by the same [scripts/make_sample_data.py](../../scripts/make_sample_data.py)
with `numpy.random.default_rng(20260727)`. 300 rows — small on purpose, this is not a showcase
task. Same generative model as `churn.csv`, plus one column:

| column | type | notes |
|---|---|---|
| `retention_call_outcome` | categorical | `churn_confirmed` / `saved` / `not_contacted` — a retention call that only happens *after* the churn decision is already made |

`churned == 1` rows get `churn_confirmed` 90% of the time and `not_contacted` 10%; `churned == 0`
rows get `saved` 90% of the time and `not_contacted` 10%. Two of the three categories therefore
determine the label almost exactly — strong, realistic leakage, not a literal copy of `churned`.

It is invisible to [foundry/tools/profiler.py](../../foundry/tools/profiler.py)'s leak heuristic
(`target_auc` is computed only for numeric columns) and survives
[foundry/teams/data_team.py](../../foundry/teams/data_team.py)'s cleaning untouched —
`customer_id` is still the only column the data team ever flags here, exactly as in `churn.csv`.

## Measured numbers (sklearn 1.9.0, logistic_regression, 5-fold stratified CV, `customer_id` dropped)

| measurement | value | vs. threshold |
|---|---|---|
| [foundry/tools/audit.py](../../foundry/tools/audit.py) target-encoded AUC for `retention_call_outcome` | 0.9962 | ≥ `audit_leak_auc_threshold` (0.95) — **invalidated as `leakage`** |
| CV roc_auc *with* the leak column (what a naive pipeline reports) | 0.9989 | below `audit_suspicious_metric_ceiling` (0.999) — the leakage-evidence floor is what actually catches this fixture, not the metric ceiling |
| CV roc_auc *without* the leak column (post-remediation) | 0.7630 | below `target_value` (0.90) — the run continues searching honestly after remediation, same as `churn.csv` |
| exact-duplicate row rate | 0.000 | below `audit_duplicate_row_rate` (0.05) — this fixture exercises the `leakage` code floor specifically, not `contamination` |

Regenerate with `uv run python scripts/make_sample_data.py`; both files are deterministic and
should come out byte-identical. If a regeneration ever changes these numbers enough to fall
below `audit_leak_auc_threshold`, fix the generator, not the threshold.

# energy.csv

M8's third showcase task and the first **regression** task this repo ships, generated by the same
[scripts/make_sample_data.py](../../scripts/make_sample_data.py) with
`numpy.random.default_rng(20260728)`. Deterministic — regenerating produces byte-identical output.
900 rows, 10 columns, target `monthly_kwh` (continuous).

## Columns

| column | type | notes |
|---|---|---|
| `building_id` | str | `BLDG-00001`… unique per row. Not a feature — the same leakage trap `customer_id` is in churn.csv. |
| `floor_area_m2` | float | 45–480 |
| `n_occupants` | int | Poisson(3.2), clipped to 1–12 |
| `building_age_years` | int | 0–80 |
| `hvac_type` | categorical | `gas` .35 / `electric` .30 / `heat_pump` .25 / `none` .10 |
| `insulation_grade` | categorical | `average` .45 / `poor` .30 / `good` .25 |
| `avg_setpoint_c` | float | **missing whenever `hvac_type == "none"`** — structural: there is no heating system to set a point for (~90 rows, ~10%) |
| `solar_kw` | float | mostly 0 (75% of rows); **missing whenever `has_smart_meter == 0`** — a dumb meter can't report solar generation (~378 rows, ~42%), a second, independent structural-missingness pattern from `avg_setpoint_c`'s |
| `has_smart_meter` | int | 0/1, p = .55 |
| `monthly_kwh` | float | **target**, continuous, clipped at a 40 kWh floor (hit by 1 row out of 900) |

## Generative model

```
monthly_kwh = 140 + 0.55*floor_area_m2 + 14*n_occupants + 0.45*building_age_years
            + insulation_effect + hvac_effect + setpoint_effect
            + 0.08*floor_area_m2*(insulation == poor)   # genuine interaction
            - 2.2*solar_kw + N(0, 70)

insulation_effect: poor +70 / average +15 / good -35
hvac_effect: electric +55 / gas +10 / heat_pump -35 / none -85
setpoint_effect: 7*(avg_setpoint_c - 20) when hvac_type != "none", else 0
```

The interaction term (a large, poorly-insulated building loses disproportionately more heat than
either factor alone predicts) means a plain linear model captures most, but not all, of the signal
— the same shape as churn.csv's `new_on_mtm` term.

## Measured 5-fold KFold CV (rmse, sklearn 1.9.0 — the sandbox image's pin)

| model family (regression estimator) | rmse |
|---|---|
| `logistic_regression` (`Ridge`) | 71.843 |
| `gradient_boosting` (`GradientBoostingRegressor`) | 75.330 |
| `random_forest` (`RandomForestRegressor`) | 79.079 |

The linear baseline winning is deliberate, for the same reason as churn.csv: it lets the principal
reach `diminishing_returns` honestly after a few experiments instead of climbing forever.
`DatasetSpec.target_value = 65.0` (see
[foundry/datasets.py](../../foundry/datasets.py)) sits below all three measured baselines — rmse is
lower-is-better (`foundry/leaderboard.py`'s `metric_direction`), so `target_met` stays a
reachable-but-unmet stop condition, never firing on the first result.

`ExperimentSpec.model_family`'s literal names a model *family*, not a concrete sklearn class:
`foundry/stubs.py`'s per-`(family, task_type)` estimator table maps `logistic_regression` to the
linear baseline for a task — `LogisticRegression` for classification, `Ridge` for regression — the
same family name meaning "the linear baseline" in both cases.
